# Reflection, memory and agent-security methods

These optional skills deepen existing roles; the catalog remains 35 profiles.

| Method | Owner | Evidence/output |
| --- | --- | --- |
| structured-reflection | The current attempt owner; evidence-validator checks conclusions | Short observed-failure/assumption/correction record, with actual rechecks separate from proposals |
| project-memory | The current task owner or team-lead | Scope/freshness/sensitivity decisions, included/excluded IDs and proposed versus performed memory operations |
| agent-security-review | security-auditor | Input-to-action trust ledger, bounded synthetic attacks, benign controls and actual enforcement evidence |

A routine success does not require reflection. An unavailable evidence artifact
supports an insufficient-evidence result. A proposed lesson remains a candidate;
accepted truth, memory and the transcript are different artifacts. No procedure
provisions a provider, uploads records or promotes memory without task authority.
The skill references map optional serialization to exact canonical Harness contracts.

For an agent integration, prompts and model refusals are evidence about observed
behavior; trusted tool-boundary checks enforce authority. Review retrieved content,
tool results, memory and child handoffs as possible untrusted sources. Isolated
stubs do not establish production protection. General application security stays
with security-review; the focused procedure adds agent-specific paths.

[Evaluations](../evals/README.md) distinguishes explicit-procedure tasks, catalog
selection trials, independent reviews and unexecuted specifications. Read only
relevant skill references; missing skills remain explicit capabilities and never
trigger automatic installation.
