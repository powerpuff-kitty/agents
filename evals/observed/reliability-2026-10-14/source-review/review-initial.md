# Independent initial source review

Scope: the three requested skills, evaluator discovery/new-case support and named shared/security instructions, with local canonical reflection and memory contracts. Source and acceptance-spec review only; no model execution or production integration tested.

## Findings

**F1 — P2: discovery task generation omits the catalog for all three new cases (observed initial source; root fix pending separate verification).** `agents/scripts/behavior_eval.py:88-89,101` creates the new-case task using lower-case `using the supplied role and optional skill.`; its discovery rewrite initially matched only `Use the supplied role and optional skill;` and older explicitly named quality/GEO forms. Discovery omits `instructions/role.md` and `instructions/skill`, so these tasks refer to supplied instructions that do not exist at those explicit-mode locations and never point to `catalog.md`. A model can fail instruction selection for a harness defect, rather than a catalog defect. Generate discovery tasks directly or match every supported template, and add tests for all three new cases. First read observed this; root reported adding the missing replacement before hash capture. The initial hash manifest is therefore post-fix. `temporal-drift.json` records that limitation and the reconstructed earlier script identity; no historical hash capture is claimed.

**F2 — P2: discovery does not route the shared operating contract into the selected instructions.** `agents/scripts/behavior_eval.py:47-49` stages `operating-contract.md`, but catalog construction at 38-49 advertises only skill/role entries, and the task at 101-102 only points to `catalog.md`. Explicit mode appends the shared contract at 53. The reviewed `agents/security-auditor/instructions.md` also has no shared-contract reference. Consequently discovery and explicit trials do not have an equivalent instructed operating contract: a compliant trial can select the role and procedure without encountering the shared preservation, authorization and completion rules. Add a mandatory shared-contract path in the task/catalog (before optional selection) and assert it for every case. Staging a file alone is not evidence that a trial loaded it.

**G1 — acceptance-spec/coverage gap, not an observed model failure:** all cases within each new skill reuse the same prompt and generic single acceptance criterion (`tests/cases.json`). Variant requirements are descriptive strings rather than retained variant inputs. For example, structured-reflection's `insufficient-evidence` and `no-reflection-needed` prompts still ask to reflect on the failed attempt; agent-security-review's `memory-poisoning` and `benign-control` have no supplied matching fixture; memory cases do not specify exact included/excluded IDs or promotion decisions. The files correctly say not-run, but they do not yet give a reviewer discriminating pass/fail expectations for the advertised cases. Add case-specific fixtures or explicit transformations and concrete acceptance criteria, keeping runtime outcomes unclaimed until run. The scoped evaluator tests cover only the older cases plus one older discovery case; they do not exercise the three new preparation branches.

## Skill quality and compatibility

The procedures are compact and avoid major scope/authority errors: they separate observations from execution, proposed corrections/memory operations from actual authority, source/model refusal from backend enforcement, and candidates from accepted truth. Optional serialization is appropriately separate from the base procedure. The inspected reflection field/status guidance and memory sensitivity/lifecycle guidance are consistent with the allowed canonical contracts. This is source comparison, not complete schema/semantic validation or validation of remote pinned URLs. No actionable schema incompatibility was found in inspected prose.

The templates are generic across all three skills. Adding short domain-specific fields (attempt/evaluation/correction/recheck; query/include/exclude/promotion ledger; attack/control/source/sink/benign result) would make required evidence easier to retain. This is an optional usability improvement. The main skill documents are short; no excessive main-procedure content needs removal. Repeated boilerplate in case specifications provides little discriminating coverage and is better replaced by case-specific checks than expanded.
