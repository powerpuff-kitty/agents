## Implementation assessment

The helper now hashes raw `git ls-files --stage -z` output. The records include mode, blob object ID, stage, and path; NUL-delimited bytes avoid filename quoting/line ambiguities and decoding dependencies. SHA-256 compactly preserves this semantic identity. The helper explicitly supplies `GIT_OPTIONAL_LOCKS=0` and does not compare raw index stat-cache bytes.

Preparation captures the identity for Git fixtures while source archives still keep null source revisions. Grading retains the porcelain status check separately and compares the prepared semantic identity for the focused-review case. A missing or null initial identity produces Python `None` / JSON null, which is unknown and falsey. Consequently the repository's `all(checks.values())` idiom cannot turn this missing evidence into a pass. Existing `review_verdict='unverified'` remains intact.

If the fixture `.git` directory is deleted, grading returns false for the porcelain-preservation check and false for known semantic staging evidence, rather than falling through to an enclosing repository or raising merely because the directory is missing. When initial identity is also missing, the semantic result remains unknown; neither combination becomes passing evidence. This assessment verifies deletion of the fixture Git directory, not arbitrary corruption or unsupported replacement of its internal Git structures.

## Meaningful regression evidence

The added staging regression changes the staged blob directly through hash-object/update-index, sets assume-unchanged, and asserts both porcelain output and workspace hashes remain identical. It then checks that the former status/source checks remain true while the new staging check and aggregate truthiness fail. This establishes the required status-only false-pass condition without relying on a workspace-source mutation already caught by the old hash check. The independently retained baseline probe previously demonstrated that the old implementation passed every deterministic check for this same condition.

The added legacy test removes the metadata key, requires a null preservation result, verifies aggregate falseyness, and keeps the reasoning verdict unverified. The third added test checks semantic identity through a timestamp refresh and catches deletion of fixture Git metadata. Existing source-archive and other-fixture behavior tests remain present and passing.

The timestamp regression by itself does not assert that raw index bytes changed; this review's independent stat-cache probe supplies that stronger evidence. It changes mtime, refreshes the synthetic index, records changed raw index hashes, and obtains unchanged semantic identity plus true preservation checks. `git update-index --refresh` exits 1 with `display.py: needs update` because that fixture deliberately contains an unstaged edit; the nonzero result is retained rather than reported as a successful Git command.
